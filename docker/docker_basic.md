# 도커 관련 강의를 듣고 정리한 곳입니다. 

# 도커를 쓰는 이유 
도커가 없다면 내가 앱을 개발했는데 앱을 실행하는데 필요한 데이터베이스, 웹서버 등등의 어플을 사용자 컴퓨터에 일일히 설치해야 한다. 
하지만 이러한 환경설정을 하는것은 매우 귀찮을 뿐더러 에러가 날 확률이 높다. 따라서 개발자가 이러한 환경설정을 미리 해둔 다음에 사용자에게 제공해주면 좋지 않을까? 싶어서 나온게 도커이다. 

도커는 기본적으로 리눅스에서 실행된다. 만약 윈도우나 맥북에서 도커를 사용하고 싶다면 리눅스를 가상머신으로 실행해야 한다.(이 부분은 도커가 알아서 해주기 때문에 크게 신경쓸 필요는 없음)

# 이미지 pull 
앱스토어에서 프로그램을 받고 프로그램이 프로세스를 실행시키듯이, 
docker hub에서 이미지를 pull하고 그 이미지를 run 하면 container가 실행된다. 

실습으로 아파치 웹서버가 설치되어있는 컨테이너를 다운받아보자. `docker pull httpd`로 이미지를 다운받을 수 있고, `docker images`으로 무슨 이미지를 다운 받았는지 확인 가능하다. 

# 이미지 run 
이미지를 이용해서 컨테이너를 만들고 실행하려면  `docker run --name ws1 httpd` 이런식으로 컨테이너의 이름을 지정하고 만들면 된다. 
현재 무슨 컨테이너가 실행중인지 확인하려면 `docker ps` 
중지하려면 `docker stop ws1` 
현재 컨테이너들이 무슨 상태인지 (중지된 컨테이너 포함) 확인하려면 `docker ps -a`
다시 시작하려면 `docker start ws1`
그런데 run으로 컨테이너 만들면 기본적으로 로그를 계속 보여주는 형식인데 start로 시작하면 로그는 안보여준다. 
로그를 출력하려면 `docker logs ws1`,  계속 출력하려면 `docker logs -f ws1` 
컨테이너를 삭제하려면 `docker rm ws1`
이미지를 삭제하려면 `docker rmi httpd`


# 호스트 개념 
웹서버에 접속할때는 보통 80번 포트를 사용해서 서버에 접속하면 아파치가 index.html파일을 준다. 
하지만 만약 도커위에있는 웹서버에 접속하려면 클라-호스트-컨테이너 이 순서로 접속을 해야한다. 이 상태에서 그냥 80으로 달라고 해도 컨테니어의 80으로 가지 않기 때문에 "호스트의 몇번 포트로 온건 컨테이너의 몇번포트로 보내주세요" 라고 설정을 해야한다. 
`docker run -p 8000:80 --name ws1 httpd` 이런식으로 호스트의 8000번 포트로 요청이 온건 컨테이너의 80번 포트로 보내주세요 라고 포트포워딩을 해줘야 한다. 

이 상태로 `http://localhost:8000/index.html` 으로 접속하면 제대로 동작하는걸 확인 가능하다...

# 컨테이너에서 명령어 실행 
이제 컨테이너 안에서 CLI명령어를 사용하는 법을 보자. 
`docker exec ws1 pwd` 이런식으로 사용하면 실행중인 컨테이너에서 특정 명령을 수행할 수 있다 
하지만 지속적으로 명령을 내리고 싶으면 `docker exec -it ws1 /bin/bash` 이런식으로 할 수 있다 

# 컨테이너와 호스트 연결  
컨테이너 안에서 작업하다가 만약 실수로 컨테이너를 삭제했다면? 
그런 경우를 대비해서 호스트의 폴더와 컨테이너의 폴더를 서로 연동시킬 수 있다.
`docker run -p 8888:80 -v ~/Desktop/htdocs:/usr/local/apache2/htdocs/ httpd`
이렇게 하면 내 로컬에서 작업해도 실시간으로 컨테이너에 반영되기 때문에 편리하다
